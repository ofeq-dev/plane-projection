Cited link list for Performance & video output (Topic A) and SE document standards (Topic B).
Every URL below was fetched and verified to resolve, Oct 2026. Caveats flag what is *not* primary.

## Topic A: Performance & video output

- [timeit — Measure execution time of small code snippets](https://docs.python.org/3/library/timeit.html) — official methodology for the FPS/benchmark write-up: repeat timing and report `min()` (the docs state min is "the only number you should be interested in"), GC toggling caveats, autorange
- [time.perf_counter() — Python `time` module](https://docs.python.org/3/library/time.html#time.perf_counter) — the clock to use for FPS measurement in the SRS: "highest available resolution" and monotonic; also `perf_counter_ns()` to avoid float precision loss
- [NumPy: the absolute basics for beginners](https://numpy.org/doc/stable/user/absolute_beginners.html) — official statement that NumPy "shines when there are large quantities of 'homogeneous' (same-typed) data to be processed on the CPU" (justifies the vectorized `uint8 500^3` algorithm in the SRS)
- [What is NumPy? — Why is NumPy fast?](https://numpy.org/doc/stable/user/whatisnumpy.html) — primary source that vectorized/broadcast operations are "speedily executed by pre-compiled C code" at "near-C speeds" (replaces Python-loop argument)
- [Writing Performant NumPy Code with Multi-Core CPUs](https://numpy.org/doc/stable/user/basics.performant_code.html) — the official NumPy performance page (multiprocessing/threads/joblib/threadpoolctl), for the benchmark write-up's parallelization options if vectorization alone misses 30–100 FPS
- [Getting Started with Videos (OpenCV-Python Tutorials)](https://docs.opencv.org/4.x/dd/d43/tutorial_py_video_display.html) — official `cv.VideoWriter` usage walkthrough: fourcc creation, the required `fps` and constant frame-size constructor arguments, Linux FFMPEG/Windows/MacOS backends
- [cv::VideoWriter class reference](https://docs.opencv.org/4.x/dd/d9e/classcv_1_1VideoWriter.html) — the official statement that each written frame "must have the same size as has been specified when opening the video writer" (`write()` docs, i.e. render all planes at one fixed height×width); also the fps parameter is the "framerate of the created video stream" and fourcc/MP4 codec-conversion and odd-dimension truncation notes
- [imageio-ffmpeg (PyPI)](https://pypi.org/project/imageio-ffmpeg/) — alternative mp4 writer: bundled static ffmpeg binary (~60 MiB wheels), BSD-2-Clause, Python ≥ 3.10; cite when the README explains the mp4 dependency choice
- [imageio documentation (stable)](https://imageio.readthedocs.io/en/stable/) — imageio v3 docs (FFmpeg plugin via imageio-ffmpeg); the primary page to cite for the `imageio.mimwrite`/writer API if imageio paths are used

## Topic B: SE document standards

- [ISO/IEC/IEEE 29148:2018 — Systems and software engineering — Life cycle processes — Requirements engineering](https://www.iso.org/standard/72089.html) — the SRS standard's landing page (paywalled, CHF 227; preview available in the OBP); use to cite the requirements-quality attributes and the SRS information item outline, and to state which of its 92-page process/information-item machinery the student's small project explicitly skips
- [Software Requirements Specification Template (Karl E. Wiegers, Process Impact) — PDF](https://research.cs.queensu.ca/home/emads/teaching/slides/srs_template_sep14.pdf) — the widely-used free shareware SRS template (self-labelled "downloaded from www.processimpact.com") supplying the boilerplate section skeleton (purpose, scope, functional/non-functional requirements, constraints, acceptance criteria) so the student doesn't reinvent an outline
- [IEEE 830-1998 — Recommended Practice for Software Requirements Specifications](https://standards.ieee.org/standard/830-1998.html) — the famous predecessor's landing page ("content and qualities of a good SRS... sample SRS outlines"); note it is withdrawn and superseded by ISO/IEC/IEEE 29148 — cite for outline ideas, not as the governing standard
- [Architectural Decision Records (adr.github.io)](https://adr.github.io/) — the ADR GitHub org's canonical homepage: definitions of AD/ASR/ADR, AD Practices, ADR Templates, and tooling lists — the citation for the repo's ADR convention (docs/adr/0001)
- [Documenting Architecture Decisions — Michael Nygard (Cognitect, 2011)](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions.html) — Nygard's original article defining the Title/Context/Decision/Status/Consequences format and "numbered sequentially and monotonically" rule — quote for ADR template sections
- [How to use fixtures — pytest official docs](https://docs.pytest.org/en/stable/how-to/fixtures.html) — official fixtures page: parameterized fixtures and scopes map directly onto "render each plane ∘ profile" test-case matrices and loading NRRD/CSV fixtures once per module
- [xUnit Test Patterns — Result Verification Patterns (Gerard Meszaros)](http://xunitpatterns.com/Result%20Verification%20Patterns.html) — canonical pattern vocabulary (State Verification, Custom Assertion, Delta Assertion) for the testing strategy section describing frame-vs-golden-master comparison
- [Make a README](https://www.makeareadme.com/) — README guide + editable template (Name, Installation, Usage, Contributing, License sections) for aligning the repo README with convention
- [About the repository README file — GitHub Docs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) — GitHub's own statement that the README is "often the first item a visitor will see" and what it must convey (what/how to get started/where to get help/who maintains)

## Caveats

- **Kent Beck's "Workflows of Reference Testing" could not be verified**: no such Medium post resolves under any URL (web search, Medium search, and Wayback Machine CDX captures of `medium.com/@kentbeck_7670/*` contain no "workflows-of-reference-testing" slug). Do not cite it until the exact URL is confirmed from another source; the pytest fixtures + xUnit Patterns links above cover the same vocabulary.
- **Container FPS vs processing throughput**: no canonical primary source states this distinction outright. The closest primary wording is the OpenCV `cv::VideoWriter` docs (fps parameter = "framerate of the created video stream" — metadata the container carries), and Python's `timeit` "min of repeats" guidance for the processing-rate side. State the distinction in the benchmark write-up in their own words citing those two pages.
- **Original Process Impact "goodies" page for the Wiegers template is gone**: `processimpact.com/goodies.shtml` 404s; the Queen's University mirror PDF is the reachable copy (verified 200, application/pdf).
- **NASA SRS template on GitHub**: `github.com/NASA/software-requirements-spec` 404s; no verifiable NASA-owned SRS template repo was found, so it is omitted.
- **imageio plugin listing** (`imageio.readthedocs.io/en/stable/reference/plugins.html`) 404s — only the imageio docs root is claimed.
