# Research: Projection algorithm & primitives

Annotated, verified primary-source links for the nearest-voxel sampling mechanism, point filtering, quad rasterization, and intensity normalization — for citing in the algorithm design doc instead of re-deriving them. All URLs fetched and resolved 2026-10-31.

## 1. "Closest voxel" via NumPy — integer (fancy) indexing, rounding, bounds masking

- [NumPy user guide: Indexing on ndarrays — §Integer array indexing](https://numpy.org/doc/stable/user/basics.indexing.html#integer-array-indexing) — the official definition of advanced integer indexing ("selection of arbitrary items based on their N-dimensional index"): cite for the `M[xi, yi, zi]` vectorized lookup where `xi, yi, zi` are per-sample-point index arrays of the same shape, including the documented `IndexError` behavior for out-of-bounds indices (the reason `np.clip`/masking is required before indexing).
- [NumPy user guide: Indexing on ndarrays — §Advanced indexing](https://numpy.org/doc/stable/user/basics.indexing.html#advanced-indexing) — the statement that advanced indexing "always returns a copy" and the broadcast rule `result[i_1,...,i_M] == x[ind_1[i_1,...], ind_2[i_1,...], ...]`; cite for why the whole frame plane can be sampled in one array op (no marching loops) and one memory allocation.
- [NumPy user guide: Indexing on ndarrays — §Boolean array indexing](https://numpy.org/doc/stable/user/basics.indexing.html#boolean-array-indexing) — official basis for the invalid-sample mask (out-of-plane / out-of-volume samples → boolean mask → fill "error frame" color), described as "practically identical to `x[obj.nonzero()]`".
- [`numpy.rint` API reference](https://numpy.org/doc/stable/reference/generated/numpy.rint.html) — "Round elements of the array to the nearest integer" with the exact tie sentence: "For values exactly halfway between rounded decimal values, NumPy rounds to the nearest even value"; the primary source for the round-half tie rule (`np.rint(1.5) = np.rint(2.5) = 2.0`).
- [`numpy.round` API reference](https://numpy.org/doc/stable/reference/generated/numpy.round.html) — alias `around` of the same rounding (the docs state `around` is "an alias"); cite whichever name the code uses, plus the note that it is "equivalent to `np.true_divide(np.rint(a * ...))`" for `decimals != 0`).
- [`numpy.clip` API reference](https://numpy.org/doc/stable/reference/generated/numpy.clip.html) — "values outside the interval are clipped to the interval edges"; cite for clamping candidate voxel indices to `[0, s-1]` in each axis as the vectorized bounds handling that replaces per-sample `if` checks.

## 2. Sampling/nearest-neighbor in the SciPy sense (justifying "closest voxel" as the proper simple choice)

- [`scipy.ndimage.map_coordinates` API reference](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.map_coordinates.html) — the canonical library statement "Map the input array to new coordinates by interpolation ... determined by spline interpolation of the requested order", where `order=0` is nearest-neighbor; cite it when arguing "the closest voxel is the simplest (proper) way" (order 0) vs. the interpolation option (`order` 1–5) the project deliberately did not use. Also its `mode='constant'`/`cval` parameters document the standard way out-of-volume samples are handled.
- [SciPy `ndimage` tutorial: interpolation boundary modes](https://docs.scipy.org/doc/scipy/tutorial/ndimage.html#ndimage-interpolation-modes) — the official explanations of `nearest`, `constant`, `reflect`, etc.; use instead of writing your own paragraph about how sampling fills samples that fall outside the volume.

## 3. Point sampling (nearest-neighbor filtering) as the general graphics concept

- [Heckbert, "Survey of Texture Mapping", IEEE Computer Graphics & Applications, 1986 (PDF, CMU copy)](https://www.cs.cmu.edu/~ph/texsurv.pdf) — **primary** and the standard-cited survey; its screen-scanning section is literally the project's algorithm ("for y, for x: compute u(x,y) and v(x,y), copy SCR[x,y] = TEX[u,v]") and its "filtering" half is where point sampling vs. filtered sampling is defined — cite once instead of explaining the idea yourself.
- [LearnOpenGL: Textures](https://learnopengl.com/Getting-started/Textures) — **not primary** (tutorial site); its Texture Filtering section is nonetheless the usual first reference for `GL_NEAREST` "selects the texel whose center is closest to the texture coordinate" vs. `GL_LINEAR`; useful for the reader-facing design doc, but pair or replace with Heckbert above when a citation-grade source is needed. (The even more primary Khronos OpenGL Wiki Texture Filtering page could not be verified/fetched from this environment — excluded.)

## 4. Rasterizing plane geometry by corner-point (u,v) mapping + intensity normalization to display range

- [Heckbert, "Fundamentals of Texture Mapping and Image Warping", UCB/CSD-89-516, UC Berkeley, 1989 (landing page)](https://www2.eecs.berkeley.edu/Pubs/TechRpts/1989/5504.html) — **primary** archival record (bibliographic metadata + BibTeX for citing) of the canonical thesis on mappings from pixels to quads: affine, bilinear, and projective; the bilinear (quad-corner) mapping class is exactly "map pixel (u,v) to a 3D point via the plane's defined corner/extremity points".
- [Heckbert thesis, direct PDF (CSD-89-516)](https://www2.eecs.berkeley.edu/Pubs/TechRpts/1989/CSD-89-516.pdf) — the document itself, including the shipped `pmap_quad_rect` C code ("find mapping between quadrilateral and rectangle") — citable evidence that mapping a rectangle of sample coordinates onto a plane quad/parallelogram then sampling is a solved, standardized technique.
- [Heckbert, "Projective Mappings for Image Warping" (excerpt, CMU course copy PDF)](http://graphics.cs.cmu.edu/courses/15-463/2010_spring/Papers/proj.pdf) — short excerpt of the thesis's homogeneous-notation section with the explicit worked formula for the mapping "specified by the four corners of a quadrilateral" — the most compact citable statement that four plane points + pixel (u,v) determine the sample point.
- [scikit-image: "Image data types and what they mean"](https://scikit-image.org/docs/stable/user_guide/data_types.html) — the official dtype-range table (`uint8` 0–255, `uint16` 0–65535, `uint32` 0–2³²−1) plus "you should never use `astype`... use `img_as_ubyte`... properly rescale"; cite for "we scale M's values by the file's dtype range to 0–255 for display" without writing the scaling table yourself.
- [Display side: `matplotlib.pyplot.imshow` API reference](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.imshow.html) — the official statement for a 2-D scalar array rendered with `cmap='gray', vmin=0, vmax=255` and that "Out-of-range RGB(A) values are clipped" — cite as the display-side normalization the frame canvas targets (e.g. for the SRS/MVP validation plots).
- [DICOM PS3.3 §C.11.2 VOI LUT Module + Window Center/Width](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.11.2.html) — **primary** (the standard itself): the canonical definition of linear grayscale windowing onto output range 0–255, including its Note 4 that c = 2ⁿ⁻¹, w = 2ⁿ is "a mathematical identity VOI LUT transformation" for full n-bit unsigned input — use it to define "we scale by the file's dtype range" as a DICOM-style identity/full-range window rather than content-based min–max stretching.

## Caveats

- Every URL above was fetched/resolved today (2026-10-31) except `https://www.khronos.org/opengl/wiki/Texture_Filtering`, which failed to fetch twice from this environment (transport/HTTP timeout) — it is deliberately not listed; do not cite it without manual re-verification.
- NumPy `np.rint`/`np.round` round half **to even** (documented verbatim on both pages). If the algorithm ever specifies half-**away-from-zero** tie handling ("round-half up"), that is a non-NumPy convention — either state the even-valued behavior and rely on the doc's Notes, or implement/pin an explicit rule (e.g. `np.floor(x + 0.5)`) in the algorithm doc rather than citing a library default as if it matched.
- `scipy.ndimage.map_coordinates` is cited to *justify* choosing nearest-neighbor sampling, not as the implementation: the actual lookup is plain integer fancy indexing (equivalent to `order=0`), and relying on the NumPy indexing docs (Section 1) for behavior is more accurate than implying SciPy is used at runtime.
- Heckbert's `cs.cmu.edu/~ph/` and `graphics.cs.cmu.edu` PDF links are personal/course-hosted copies and are somewhat link-rot prone; the Berkeley archive (`eecs.berkeley.edu/Pubs/TechRpts/1989/5504.html` + its PDF) is the durable archival home — prefer it for bibliographic citation and keep the CMU copies as convenience mirrors.
- "Fundamentals of Texture Mapping and Image Warping" supports **bilinear** quad↔rectangle mapping (including the degeneracy discussion for non-planar/non-convex quads in its mapping-substitution sections); the project's isosceles-triangle (3-point) case is subsumed by treating the trapezoid path with a = b (zero-width triangle) — the thesis does not define the exercise's `|dist(a,b) − dist(a,c)| < 0.001` plane-validity tolerance itself; that remains a project-spec-defined (self-authored) predicate, so no external citation can or should replace defining it in the spec.
- DICOM windowing is cited only as the canonical *concept* of intensity windowing to a 0–255 output range; "we normalize by the file's dtype range" corresponds to the standard's identity/full-input-range window (C.11.2.1.2 Note 4), and this is a linear, not content-driven, normalization — do not conflate it with matplotlib's default `vmin=min(X), vmax=max(X)` behavior on the same `imshow` page, which normalizes by the *data present* (a different rule; contrast it in the doc if both are mentioned).
