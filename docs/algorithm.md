# Algorithm — frame geometry

Normative requirements live in [`docs/srs.md`](srs.md) (FR-12/FR-13); this
document pins the discretization the renderer implements. Coordinates are
canonical voxel-index coordinates ([ADR 0002](adr/0002-canonical-voxel-index-space.md)):
no world-space header field, origin, or spacing is applied.

## Inputs

A validated row is either a triangle `(a, b, c)` or a trapezoid
`(a1, a2, b, c)` in the CSV's column order (FR-8). A triangle is the same
geometry with `a1 = a2 = a`.

- leg `L = (dist(a1, b) + dist(a2, c)) / 2` — the two legs agree within
  `EPS = 0.001` by FR-10.
- base `B = dist(b, c)`.
- frame height `H = max(1, round(L))`, width `W = max(1, round(B))`
  (FR-12b). `round` is NumPy/Python half-to-even; the `max(1, ...)` keeps
  sub-voxel planes renderable.

## Sample grid

Rows run top to bottom, `y = 0 .. H-1`, with leg parameter

```
t_y = (y + 1) / H
```

This is the lecturer's pseudocode anchor: it steps one leg sample *before*
writing each output row, so the bottom row lies on `b`/`c` and the top row is
one sample below the apex. Legs are divided into `H` equal steps, so sample
density is one sample per voxel-length unit (FR-12b).

Row endpoints and centre:

```
L_y = a1 + t_y * (b  - a1)      # left leg,  apex -> b
R_y = a2 + t_y * (c  - a2)      # right leg, apex -> c
C_y = (L_y + R_y) / 2
w_y = |R_y - L_y|
u_y = (R_y - L_y) / w_y
```

Column `x = 0 .. W-1` samples the row at pixel centre

```
o_x = x + 0.5 - W / 2
q_{x,y} = C_y + o_x * u_y
```

`o_x` is the signed distance in index units from the row centre; columns are
one unit apart, and each row is symmetric about the canvas centre. A pixel is
inside the plane's row when `|o_x| <= w_y / 2` (with `1e-9` of float dust
tolerance); otherwise it is background black. A triangle's top rows are
therefore narrow and centred, while a rectangle fills every column on every
row. There is no mirroring: `b` is the left edge and `c` the right edge.

Every sample point is computed directly from `(x, y)` — no `p += dp`
accumulation, so floating-point drift cannot build up across a frame.

## Voxel lookup and display

- Nearest voxel: `np.rint(q)` componentwise (half-to-even, FR-12a), producing
  integer indices.
- A boolean mask keeps only samples that are both inside the plane's row and
  inside `0 <= index < shape`; the mask is applied **before** fancy indexing.
  Outside `M` is black `0` (FR-12d), never a clamped edge voxel.
- Display scaling (FR-12e): unsigned dtypes map `0 .. dtype_max` to `0..255`;
  signed dtypes (tolerated, FR-4) map `dtype_min .. dtype_max` to `0..255`.
  Rounding to uint8 is again half-to-even. Values are never stretched to the
  frame's content range. Missing/outside samples stay at 0 after scaling.

## Canvas

`canvas_size` takes the max width and height over renderable frames and
rounds each up to even (FR-18/FR-19). `pad_frame` places each frame top-left
on a black canvas of that size, no centring, no aspect compensation
(FR-21). If no row renders, the placeholder canvas carries the video (FR-20).

## Hand-checked fixtures

All fixtures use `M[x][y][z] = x` as a uint8 ramp, so identity display
scaling makes every pixel value the rounded sampled x-index. The committed
goldens in `tests/golden/` are regenerated by
`python tests/generate_goldens.py`; these tables are the independent oracle.

**Triangle** `a=(2,2,0), b=(0,2,0), c=(4,2,0)`: `L=2 -> H=2`, `B=4 -> W=4`.

| row `y` | `t_y` | sample x at columns 0..3 | `rint` | expected row |

| 0 | 1/2 | –, 1.5, 2.5, – | –, 2, 2, – | `0 2 2 0` |
| 1 | 1 | 0.5, 1.5, 2.5, 3.5 | 0, 2, 2, 4 | `0 2 2 4` |
